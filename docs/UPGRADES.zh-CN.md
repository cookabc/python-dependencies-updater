# 升级策略与验证

版本号变化只能用于初步分类，不能证明升级兼容。主版本变化、Python epoch 变化，以及 `0.x` 的次要版本变化需要确认。其他更新也没有自动通过项目测试。

## 选择升级目标

以下设置均使用 `pyDepsHint` 前缀：

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| `strategy` | `latest` | `latest`：最新版本；`compatible`：同一维护线，`0.x` 限制在当前次要版本内；`patch`：同一主版本和次要版本。仍保留声明中的上界和排除条件。 |
| `targetPythonVersion` | 空 | 目标运行时的具体版本；留空时尝试读取 `.python-version`。没有具体版本时，兼容性为未知。 |
| `minimumReleaseAgeDays` | `0` | 发布冷静期，0 表示关闭；开启后排除发布时间未知的版本。冷静期不保证安全。 |
| `ignoredVersions` | `{}` | 按包名忽略指定的精确版本。 |
| `deferredPackages` | `{}` | 按包名延期到 ISO 8601 时间。 |
| `validationCommands` | `[]` | 项目检查命令，格式为 `{ "executable": "...", "args": [...] }`，不经过 shell。留空表示不运行项目测试，例如可配置 `[{"executable":"uv","args":["run","--no-sync","pytest"]}]`。 |

`Requires-Python` 按该具体解释器版本筛选。wheel 的平台可用性，以及项目声明支持的完整 Python 范围，仍需原生解析器验证。

目标运行时设置用于筛选包的元数据。验证命令使用项目及原生工具实际选择的运行时，不会自动切换 Node 或 Python 版本。

冷静期、忽略和延期规则也适用于可能修复漏洞的更新。紧急修复时应明确调整策略，扩展不会绕过设置。

启用 `checkVulnerabilities` 时，单包、批量和预览更新都会先检查目标版本的 OSV 已知漏洞。存在已知漏洞的目标会被跳过；请求失败或响应不完整会停止更新。明确关闭该设置才会跳过检查。检查覆盖已知公告，不能证明不存在其他供应链风险。

## 显示依赖报告

打开依赖声明文件，执行「显示依赖报告」。支持 `uv.lock` 和 `poetry.lock`。 报告列出锁定版本、直接或传递依赖、已知依赖链和漏洞公告链接。

锁定版本不等于实际安装版本。报告保留条件分支、可选依赖和开发组，某个包不一定在当前环境中启用。私有源和非注册表来源会保留在报告中，但锁文件报告不会把它们提交给公共 OSV。检查失败、关闭和未检查均有明确标记。

## 预览并验证依赖更新

1. 打开依赖声明文件，执行「预览并验证依赖更新」。
2. 在 VS Code 差异视图中审阅声明变更。
3. 确认项目目录、包管理器命令和项目检查，选择「Validate proposal」，在临时副本中执行。
4. 解析与检查通过后，选择「Apply changes」。声明文件和锁文件会一起作为编辑器变更应用，供审阅和保存。

临时副本验证支持根目录中的 `pyproject.toml`，并要求已有 `uv.lock` 或 `poetry.lock`；分别执行 uv lock/sync 或 Poetry lock/install。requirements 文件及嵌套 Python 工作区声明仍可使用原地更新，当前验证命令暂不支持。

验证会在临时副本中执行项目代码，使用原生包管理器自己的源和认证配置，不修改原项目的安装环境。副本不包含已有的 `node_modules`、`.venv`、`.git` 和符号链接；工作区必须受信任。依赖这些文件的检查需要按项目配置。

失败、超时或取消时会删除副本。应用前会核对原文件、未保存的声明内容和源文件快照；验证期间发生的新编辑需要重新验证。已有修改不会被重置或暂存。应用后可通过编辑器撤销，并应一起审阅和保存所有变更文件。

没有测试命令时，结果明确标注「未运行项目测试」。通过只代表所配置的检查通过。每个子进程超时为 10 分钟。命令使用参数数组，不经过 shell；Windows 的 `.cmd` 包管理器入口可能需要使用可执行包装器或项目自己的验证流程。

## 共用实现

`src/shared/` 包含策略、依赖图模型、目标版本检查、进程执行及验证和报告流程。Python 项目维护源文件，npm 项目保留同步副本，两者可独立构建和打包。两个项目同时存在时，`npm run check:shared` 检查一致性；修改源文件后运行 `node scripts/sync-shared.mjs --write`，再审阅两边差异。非默认目录可通过 `--peer <path>` 指定。
